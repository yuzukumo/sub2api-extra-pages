# Просмотр документации Sub2API

[English](README.md) | [简体中文](README.zh-CN.md) | [繁體中文（台灣）](README.zh-TW.md) | Русский

Страница для просмотра документов Markdown, предназначенная для встраивания в Sub2API. Интерфейс построен на React, TypeScript, Ant Design и `@ant-design/x-markdown`. Поддерживаются несколько документов, навигация по заголовкам, якорные ссылки, подсветка синтаксиса, копирование кода, просмотр изображений, LaTeX, Mermaid, GFM и автоматический выбор светлой или тёмной темы.

В сервисе нет редактора, входа в систему, совместной работы или административного API.

## Настройка документов

Файл списка имеет фиксированный путь: [`content/documents.json`](content/documents.json). Он обязателен, а изменить его путь через переменную окружения нельзя. Порядок элементов в массиве `documents` определяет порядок документов в левой панели.

```json
{
  "title": {
    "en-US": "Documentation",
    "zh-CN": "服务文档",
    "zh-TW": "服務說明文件",
    "ru-RU": "Документация"
  },
  "documents": [
    { "file": "introduction.md" },
    { "file": "guides/api-reference.md" }
  ]
}
```

Каждая запись содержит только поле `file`. Это путь к файлу Markdown относительно каталога языка, уникальный идентификатор документа и значение параметра `?doc=`. Название в левой панели берётся из первого заголовка `#` соответствующего файла, поэтому каждый перевод должен содержать заголовок первого уровня.

После добавления, удаления или перестановки файлов достаточно обновить страницу в браузере. Административной страницы и API для записи нет.

Для каждого документа должен существовать файл с одинаковым относительным путём во всех поддерживаемых языковых каталогах:

```text
content/
├── documents.json
├── en-US/introduction.md
├── ru-RU/introduction.md
├── zh-CN/introduction.md
└── zh-TW/introduction.md
```

В языковых каталогах можно создавать подкаталоги и хранить изображения или вложения. Используйте пути относительно текущего файла Markdown:

```markdown
![Архитектура](./images/architecture.png)
```

## Локальная разработка

```bash
npm install
npm run dev
```

Веб-интерфейс доступен по адресу `http://localhost:4174/`. Во время разработки Vite напрямую отдаёт файлы из `content`; отдельный локальный API не запускается.

Полная проверка проекта:

```bash
npm run check
```

## Развёртывание в Docker

Чтобы использовать образ, опубликованный через GitHub Actions, выполните:

```bash
docker compose pull
docker compose up -d
```

Чтобы собрать образ из исходного кода, выполните:

```bash
docker compose -f docker-compose.local.yml up -d --build
```

Nginx отдаёт статический интерфейс и файлы Markdown. В примере Compose адрес `127.0.0.1:6002` сопоставлен с портом `3000` внутри контейнера, а каталог `./content` подключён к `/usr/share/nginx/html/content` в режиме только для чтения. При необходимости измените адрес или порты в `docker-compose.yml`.

Это подключение каталога с хоста, а не именованный том Docker, поэтому оно не отображается в `docker volume ls`. Сведения о нём находятся в разделе `Mounts` вывода `docker inspect sub2apiextra-documentviewer`.

По умолчанию страница следует системной теме. Выбранные вручную тема и язык сохраняются в браузере. Интерфейс и документы доступны на английском, русском, упрощённом китайском и традиционном китайском (Тайвань). Если предпочитаемый язык браузера не поддерживается, используется английский.
